# S0.2 — AWS

> **Procedimento pesquisado em 29/09/2026** na documentação oficial da AWS:
> [`aws login`](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sign-in.html),
> [MFA da root](https://docs.aws.amazon.com/IAM/latest/UserGuide/enable-virt-mfa-for-root.html),
> [preço do AWS Budgets](https://aws.amazon.com/aws-cost-management/aws-budgets/pricing/),
> [instalação do SAM CLI](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/install-sam-cli.html),
> [Lambda](https://aws.amazon.com/lambda/pricing/).
> Conferido: o Always Free continua valendo para contas antigas (Lambda 1 milhão de requisições e 400 mil GB-s por mês; EventBridge Scheduler 14 milhões de invocações por mês; 2 orçamentos com ação grátis).

## 1. Objetivo e tempo

Proteger a conta AWS antiga e criar um acesso de desenvolvimento seguro para o agente, **sem nenhuma chave de acesso fixa**. Com isso, o agente pode auditar a conta e criar, por código, os orçamentos, o provedor OIDC do GitHub e o kill-switch.

- **Tempo estimado:** 45 a 60 minutos.
- **Como o acesso funciona (D017):** você cria um usuário IAM com MFA. O AWS CLI entra com `aws login`, pelo navegador, e recebe **credenciais temporárias** que valem até 12 horas. Não existe *access key* guardada no computador. Depois de 12 horas, basta rodar `aws login` de novo.

## 2. Pré-requisitos

- E-mail e senha da **conta root** da AWS.
- Um app autenticador no celular (Google Authenticator, Microsoft Authenticator, 1Password, Bitwarden etc.).
- Um gerenciador de senhas para guardar a senha do novo usuário IAM.
- PowerShell aberto na pasta do projeto.

## 3. Passo a passo

### Passo 1 — Entrar como root

1. Abra <https://console.aws.amazon.com> → **Root user** → e-mail → senha.
2. No canto superior direito, escolha a região **US East (N. Virginia) us-east-1**.

### Passo 2 — MFA na conta root

1. Canto superior direito: clique no **nome da conta** → **Security credentials**.
2. Seção **Multi-factor authentication (MFA)** → **Assign MFA device**.
3. **Device name:** `root-celular` → **Authenticator app** → **Next**.
4. **Show QR code** → leia com o app autenticador.
5. Digite dois códigos **seguidos** (**MFA code 1** e, depois de até 30 s, **MFA code 2**) → **Add MFA**.
6. **Recomendado:** repita o processo com um segundo dispositivo (outro app ou uma *passkey*). A AWS aceita até 8. Sem nenhum MFA disponível, a recuperação da root exige contato com o suporte.

### Passo 3 — Remover chaves de acesso da root

Na mesma página **Security credentials**, seção **Access keys**:

- Se houver alguma chave (de cursos antigos, por exemplo): **Actions** → **Deactivate** → depois **Delete**.
- Anote se existia alguma e conte ao agente. Isso é um indício para a auditoria da conta.

### Passo 4 — Faturamento: acesso e alertas

1. Menu do **nome da conta** → **Account** → role até **IAM user and role access to Billing information** → **Edit** → marque **Activate IAM Access** → **Update**. Assim, o usuário IAM e o agente conseguem criar e ler orçamentos.
2. Abra **Billing and Cost Management** → **Billing preferences** → bloco **Alert preferences** → **Edit** → marque **Receive AWS Free Tier alerts**, confirme o e-mail → **Update**.
3. Ainda em **Billing and Cost Management** → **Bills**: veja se o mês atual tem alguma cobrança. Se tiver, conte ao agente o valor e o serviço (não é segredo).

### Passo 5 — Instalar o AWS CLI v2

O AWS CLI **não está instalado** nesta máquina (verificado em 29/09/2026). No PowerShell:

```powershell
msiexec.exe /i https://awscli.amazonaws.com/AWSCLIV2.msi
```

Siga o instalador (Next → Install). **Feche e abra de novo** o PowerShell e o VS Code, e confira:

```powershell
aws --version
```

O resultado precisa ser `aws-cli/2.32.0` ou mais novo. O comando `aws login` não existe em versões anteriores.

### Passo 6 — Criar o usuário IAM de desenvolvimento

1. Na barra de busca do console, digite **IAM** → **Users** → **Create user**.
2. **User name:** `adriano-dev`.
3. Marque **Provide user access to the AWS Management Console**. Se perguntar, escolha **I want to create an IAM user**.
4. **Console password:** **Custom password** → uma senha forte, guardada no gerenciador de senhas. Pode desmarcar *Users must create a new password at next sign-in*.
5. **Next** → **Permissions options:** **Attach policies directly** → pesquise e marque:
   - `AdministratorAccess`
   - `SignInLocalDevelopmentAccess` (é ela que permite o `aws login`)
6. **Next** → **Create user**.
7. Anote a **Console sign-in URL** mostrada (formato `https://<número-da-conta>.signin.aws.amazon.com/console`).

> **Por que administrador?** Na S0 e na S1, o agente cria papéis IAM, o provedor OIDC, orçamentos e Lambdas. Criar papéis IAM já equivale a poder tudo. A proteção vem do MFA, das sessões de no máximo 12 horas e de nenhuma chave fixa. Na S8, o acesso será reduzido: o deploy passa a ser só pelo CI (papel OIDC com permissões mínimas). Registrado em D017.

### Passo 7 — Entrar como o usuário IAM e ligar o MFA dele

1. Saia da root (menu da conta → **Sign out**).
2. Abra a **Console sign-in URL** do passo 6 → usuário `adriano-dev` + senha.
3. Menu do nome (canto superior direito) → **Security credentials** → **Assign MFA device** → mesmo procedimento do passo 2 (nome `adriano-dev-celular`).
4. Saia e entre de novo para confirmar que o MFA é pedido.

A partir daqui, **não use mais a root no dia a dia**.

### Passo 8 — Conectar o AWS CLI (`aws login`)

1. No navegador padrão, esteja logado como **`adriano-dev`** (não como root).
2. No PowerShell:

   ```powershell
   aws login --profile telegrana
   ```

3. Quando pedir **AWS Region**, digite `us-east-1`.
4. O navegador abre: escolha a sessão do **`adriano-dev`** e confirme. Volte ao terminal.

### Passo 9 — Testar

```powershell
aws sts get-caller-identity --profile telegrana
```

O campo `Arn` precisa terminar em `:user/adriano-dev`. Se terminar em `:root`, rode `aws logout --profile telegrana`, saia da root no navegador e repita o passo 8.

### Passo 10 — Caminhos longos no Windows (para o SAM)

Em um **PowerShell como Administrador**:

```powershell
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force
```

Esse passo vem da documentação oficial do SAM, que recomenda caminhos longos no Windows. É a única alteração de sistema desta fase; rode você mesmo.

### Passo 11 — Instalar o AWS SAM CLI

1. Baixe e execute: <https://github.com/aws/aws-sam-cli/releases/latest/download/AWS_SAM_CLI_64_PY3.msi>.
2. Abra um PowerShell novo e confira: `sam --version` → `SAM CLI, 1.x`.

### Passo 12 — Autorizar o agente

Diga no chat: **"S0.2 concluída; autorizo a auditoria da conta e a criação dos orçamentos, do OIDC do GitHub e do kill-switch."**

O que o agente fará em seguida:

1. **Auditoria somente leitura**, em todas as regiões, de recursos esquecidos (EC2, EBS, snapshots, IP elástico, NAT, RDS, S3 etc.). Ele mostra a lista a você **antes de apagar qualquer coisa**.
2. Criação, por IaC, dos orçamentos (*zero spend* e US$ 1/mês), do provedor OIDC do GitHub e do kill-switch.

## 4. O que entregar ao agente e como

| O quê | Onde | Segredo? |
|---|---|---|
| `AWS_PROFILE=telegrana` e `AWS_REGION=us-east-1` | `.env.local` (já vêm preenchidos) | não |
| Sessão ativa do `aws login` | na sua máquina (`%USERPROFILE%\.aws\login\cache`) | sim, mas temporária e nunca copiada |
| Se havia chaves na root e se havia cobrança no mês | chat | não |

**Nunca** crie *access keys* nem cole senha, código MFA ou credencial no chat.

## 5. Checklist de verificação

```powershell
python scripts/check_setup.py s0.2
```

Deu certo quando aparecem `[ OK ]` para: AWS CLI 2.32+, perfil autenticado como `adriano-dev` (não root), região `us-east-1`, MFA na root, root sem chaves, MFA no usuário IAM, usuário sem chaves fixas, situação do AWS Organizations e SAM CLI instalado.

## 6. Erros comuns

| Sintoma | Causa e solução |
|---|---|
| `aws : O termo 'aws' não é reconhecido` | O terminal foi aberto antes da instalação. Feche e abra de novo; o caminho é `C:\Program Files\Amazon\AWSCLIV2\`. |
| `Invalid choice: 'login'` | AWS CLI antigo. Reinstale pelo passo 5. |
| `AccessDenied ... signin:AuthorizeOAuth2Access` | Falta a política `SignInLocalDevelopmentAccess` no usuário (passo 6.5). |
| O navegador abriu num perfil sem login | Entre como `adriano-dev` nessa janela e continue; ou copie a URL mostrada no terminal para o navegador certo. |
| `Arn` termina em `:root` | Você escolheu a sessão da root. `aws logout --profile telegrana` e repita o passo 8. |
| `ExpiredToken` / `The security token included in the request is expired` | A sessão passou de 12 horas: `aws login --profile telegrana`. |
| O SAM não enxerga as credenciais do `aws login` | Versões antigas de SDK. Crie um perfil ponte (a documentação oficial prevê isso): em `%USERPROFILE%\.aws\config`, adicione `[profile telegrana-sam]` com `credential_process = aws configure export-credentials --profile telegrana --format process` e `region = us-east-1`. Avise o agente. |
| Erro de relógio (`Signature expired`) | Sincronize o relógio do Windows: Configurações → Hora e idioma → **Sincronizar agora**. |
| Perdeu o celular com o MFA | Use o segundo dispositivo do passo 2.6; sem ele, siga *Recovering a root user MFA device* na documentação da AWS. |
