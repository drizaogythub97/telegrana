> **Procedimento pesquisado em 29/09/2026** na documentação oficial do Neon:
> [planos](https://neon.com/docs/introduction/plans), [branches](https://neon.com/docs/manage/branches),

> Conferido: o plano Free continua **sem cartão**, com 100 CU-hora por projeto por mês, 0,5 GB por projeto, 10 branches, restauração de 6 horas e *scale-to-zero* após 5 minutos (não dá para desligar). O Postgres 18 está disponível.

## 1. Objetivo e tempo

Criar o banco do Telegrana no Neon, com uma branch de produção e uma de desenvolvimento, e entregar ao agente as strings de conexão do papel dono. O agente usa essas strings só para criar os papéis `migrator` e `app` na S1.

- **Tempo estimado:** 15 minutos.
- **Decisão D018:** não haverá Postgres local com Docker. Os testes na sua máquina usam a branch `dev`; o CI usa um Postgres em container do próprio GitHub Actions. Nada a instalar.

## 2. Pré-requisitos

- S0.1 concluída (conta do GitHub com 2FA, recomendada para entrar no Neon).
- Dependências do validador instaladas (uma vez só):

  ```powershell
  python -m pip install --require-hashes -r scripts/requirements-check.txt
  ```

## 3. Passo a passo

### Passo 1 — Criar a conta

1. Abra <https://console.neon.tech/signup>.
2. Escolha **Continue with GitHub** (recomendado) ou Google/e-mail.
3. **Se em algum momento pedirem cartão de crédito: pare e avise o agente.** O plano Free não exige.

### Passo 2 — Criar o projeto

Na tela de criação (*Create project* / **New Project**):

| Campo | Valor |
|---|---|
| **Project name** | `telegrana` |
| **Postgres version** | **18** |
| **Cloud provider** | **AWS** |
| **Region** | **AWS US East 1 (N. Virginia)** — `aws-us-east-1` |
| **Neon Auth** | **desligado** |

Clique em **Create project**. **A região não pode ser trocada depois.** Se errar, apague o projeto e crie de novo (ainda está vazio).

O projeto nasce com a branch **`production`**, o banco `neondb` e o papel dono `neondb_owner`.

### Passo 3 — Criar a branch `dev`

1. Menu lateral → **Branches** → **New branch**.
2. **Parent branch:** `production`.
3. **Branch name:** `dev`.
4. **Data:** **Current data** (o banco está vazio mesmo).
5. ⚠️ **Auto-delete / expiration:** **desligue**. O padrão atual do Neon apaga a branch nova em **1 dia**.
6. **Create**.
7. Confira na lista de branches que a `dev` **não** mostra data de expiração.

### Passo 4 — Copiar as strings de conexão (papel dono, conexão direta)

1. Menu lateral → **Dashboard** do projeto → botão **Connect**.
2. Selecione **Branch:** `production` · **Database:** `neondb` · **Role:** `neondb_owner`.
3. **Desligue** o **Connection pooling**. O host **não** pode conter `-pooler`: a conexão direta é a certa para criar papéis e rodar migrações.
4. Mostre a senha, se estiver oculta, e copie a string inteira. Ela começa com `postgresql://neondb_owner:`.
5. Cole no `.env.local` em `NEON_OWNER_URL_PROD=`.
6. Repita com **Branch:** `dev` e cole em `NEON_OWNER_URL_DEV=`.

O endereço das duas é diferente: cada branch tem o próprio endpoint `ep-...`.

### Passo 5 — Não mexer em mais nada

Não crie tabelas nem papéis, e não ligue *Data API* nem *Neon Auth*. O agente faz tudo por migração versionada na S1.

## 4. O que entregar ao agente e como

| O quê | Onde | Segredo? |
|---|---|---|
| `NEON_OWNER_URL_PROD` | `.env.local` | **sim** (contém a senha do dono) |
| `NEON_OWNER_URL_DEV` | `.env.local` | **sim** |

Depois, diga no chat: **"S0.3 concluída"**. Nunca cole as strings no chat.

## 5. Checklist de verificação

```powershell
python scripts/check_setup.py s0.3
```

Deu certo quando, para as duas branches, aparecem `[ OK ]` para: conexão com TLS verificado (`verify-full`) como `neondb_owner`, Postgres 18, e papel dono capaz de criar os papéis `migrator` e `app`.

## 6. Erros comuns

| Sintoma | Causa e solução |
|---|---|
| `pacotes psycopg/certifi não instalados` | Rode o comando de instalação da seção 2. |
| AVISO `string com pooler` | Copiou com *Connection pooling* ligado. Refaça o passo 4 com ele desligado. |
| `as duas strings apontam para o mesmo endpoint` | Copiou duas vezes a mesma branch. Troque o seletor **Branch** na janela **Connect**. |
| `password authentication failed` | Senha cortada na cópia. Copie de novo ou use **Reset password** do papel (**Roles**), e atualize as duas variáveis se necessário. |
| `o host não está em us-east-1` | Projeto criado em outra região. Apague e recrie (passo 2). |
| A branch `dev` sumiu no dia seguinte | Estava com expiração automática. Recrie pelo passo 3 com a expiração desligada. |
| `Postgres 17` ou menor no AVISO | Versão errada na criação. Com o projeto vazio, vale recriar com a 18. |
