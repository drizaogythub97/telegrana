# S0.5 — Telegram

> **Procedimento pesquisado em 29/09/2026** na documentação oficial do Telegram:
> [recursos de bots / BotFather](https://core.telegram.org/bots/features),
> [obter api_id](https://core.telegram.org/api/obtaining_api_id),
> [contas de teste](https://core.telegram.org/api/auth).
> Conferido: *username* de bot com 5 a 32 caracteres, terminado em `bot` e **impossível de trocar depois**; um `api_id` por número de telefone; Bot API de teste em `https://api.telegram.org/bot<token>/test/<MÉTODO>`; números de teste `99966XYYYY` com código de login igual ao número do DC repetido 5 vezes. O @BotFather agora também tem um *Mini App* com as mesmas funções; este guia usa os comandos de texto, que continuam valendo.

## 1. Objetivo e tempo

Criar os dois bots reais (produção e desenvolvimento), obter o `api_id`/`api_hash` usados nos testes automáticos e informar o seu id de admin.

- **Tempo estimado:** 25 minutos.
- O bot do **servidor de testes** o agente cria sozinho na S1.

## 2. Pré-requisitos

- Telegram no celular ou no computador, logado na sua conta.
- S0.3 concluída não é necessária; esta fase é independente.

## 3. Passo a passo

### Parte A — Bots no @BotFather

#### Passo 1 — Bot de produção

1. No Telegram, abra **@BotFather**. Confira o **selo azul de verificado**: há imitações.
2. Envie `/newbot`.
3. **Nome de exibição:** `Telegrana`.
4. **Username:** `TelegranaBot`. Se estiver ocupado, tente nesta ordem: `TelegranaAppBot`, `TelegranaFamiliaBot`, `Telegrana_Bot`, `MeuTelegranaBot`. **O username não pode ser trocado depois.**
5. O BotFather responde com o **token** (formato `123456789:AA...`). Copie para o `.env.local` em `TELEGRAM_BOT_TOKEN_PROD=` e o username (sem `@`) em `TELEGRAM_BOT_USERNAME_PROD=`.

#### Passo 2 — Bot de desenvolvimento

1. `/newbot` de novo.
2. **Nome:** `Telegrana Dev` · **Username:** `TelegranaDevBot` (ou variação).
3. Token → `TELEGRAM_BOT_TOKEN_DEV=` · username → `TELEGRAM_BOT_USERNAME_DEV=`.

#### Passo 3 — Impedir entrada em grupos (nos dois bots)

1. `/setjoingroups` → escolha o bot de produção → **Disable**.
2. `/setjoingroups` → escolha o bot de dev → **Disable**.

Não mexa em descrição, foto nem comandos. O agente configura tudo isso na S1 (a foto, com a logo recortada, depois da sua aprovação).

#### Passo 4 — Limpar os tokens do chat

Depois de copiar os tokens, apague no @BotFather as duas mensagens que os contêm (segure a mensagem → **Apagar**).

#### Passo 5 — Descobrir o seu id (admin)

1. Abra o bot de dev: `https://t.me/<username-do-bot-de-dev>` → **Iniciar**. Ele não responde nada ainda; é normal.
2. No PowerShell, na pasta do projeto:

   ```powershell
   python scripts/check_setup.py --descobrir-admin-id
   ```

3. Copie o número mostrado para `ADMIN_TELEGRAM_ID=` no `.env.local`.

### Parte B — `api_id` e `api_hash` (my.telegram.org)

Servem **só** para os testes automáticos no **servidor de testes** do Telegram, com contas de teste `99966…`. **Sua conta real nunca será logada por esse cliente.**

#### Passo 6 — Entrar

1. No navegador: <https://my.telegram.org>.
2. Telefone no formato internacional: `+55 DD 9XXXX-XXXX` → **Next**.
3. O código chega **dentro do Telegram**, numa mensagem da conta oficial "Telegram", e não por SMS. Digite → **Sign In**.

#### Passo 7 — Criar o aplicativo

1. Clique em **API development tools**.
2. Preencha:

   | Campo | Valor |
   |---|---|
   | **App title** | `Telegrana Testes` |
   | **Short name** | `telegranatestes` (5 a 32 caracteres, só letras e números) |
   | **URL** | (em branco) |
   | **Platform** | **Desktop** |
   | **Description** | `Testes automatizados do bot Telegrana no servidor de testes` |

3. **Create application**.

#### Passo 8 — Copiar

1. **App api_id** (número) → `TELEGRAM_API_ID=`.
2. **App api_hash** (32 caracteres) → `TELEGRAM_API_HASH=`.
3. Ignore o resto da página (servidores MTProto e chaves públicas; o agente já conhece a configuração de teste).
4. Clique em **Log out**.

## 4. O que entregar ao agente e como

| O quê | Onde | Segredo? |
|---|---|---|
| `TELEGRAM_BOT_TOKEN_PROD`, `TELEGRAM_BOT_TOKEN_DEV` | `.env.local` | **sim** |
| `TELEGRAM_BOT_USERNAME_PROD`, `TELEGRAM_BOT_USERNAME_DEV` | `.env.local` | não |
| `TELEGRAM_API_ID` | `.env.local` | não (mas não divulgue) |
| `TELEGRAM_API_HASH` | `.env.local` | **sim** |
| `ADMIN_TELEGRAM_ID` | `.env.local` | não (mas não precisa ser público) |

Depois, diga no chat: **"S0.5 concluída"** e, se o `@TelegranaBot` estava ocupado, qual username ficou.

## 5. Checklist de verificação

```powershell
python scripts/check_setup.py s0.5
```

Deu certo quando aparecem `[ OK ]` para: os dois tokens válidos e de bots diferentes, os usernames conferindo, os dois bots fora de grupos, `api_id`/`api_hash` no formato certo e o `ADMIN_TELEGRAM_ID` encontrado como conversa privada com o bot de dev. O `api_hash` só é validado de verdade no primeiro teste E2E da S1.

## 6. Erros comuns

| Sintoma | Causa e solução |
|---|---|
| `Sorry, this username is already taken` | Use a próxima variação do passo 1.4. |
| Token vazou (foi colado em algum lugar) | @BotFather → `/revoke` → escolha o bot → gere um novo e atualize o `.env.local`. |
| Popup **"ERROR"** ao criar o aplicativo em my.telegram.org | Problema conhecido e intermitente. Desligue VPN, bloqueador de anúncios e tradutor automático; tente outro navegador ou uma janela anônima; confira se o *short name* tem só letras e números; se persistir, tente mais tarde. |
| O código de login do my.telegram.org não chega | Ele vem no chat "Telegram" do próprio app, não por SMS. |
| `--descobrir-admin-id` não acha nada | Você não tocou em **Iniciar** no bot de **dev** (e não no de produção), ou o token de dev está errado. |
| `ainda pode ser adicionado a grupos` | Refaça o passo 3 para o bot indicado. |

**Cuidados:** cada número de telefone só tem um `api_id`. O Telegram monitora clientes não oficiais e bane quem usa a API para spam. Por isso o agente usa essas credenciais **exclusivamente** no servidor de testes, com contas de teste.
