## 1. Objetivo e tempo

Criar o repositório **público** `telegrana`, ligar as proteções gratuitas de segurança e deixar o Claude Code com acesso de leitura e escrita a ele.

- **Tempo estimado:** 15 minutos.
- **Por que público?** Decisão D015 (29/09/2026): em repositório privado de conta pessoal, o secret scanning e o push protection do GitHub são pagos. No público, são grátis. Consequência: **nada pessoal entra no repositório** (o `.gitignore` já protege `.env.local` e `tests/eval/data/`).

## 3. Passo a passo

### Passo 1 — E-mail privado (obrigatório em repositório público)

Seu e-mail pessoal ficaria visível em cada commit. O agente já configurou este repositório para usar o e-mail *noreply* do GitHub. Complete do lado do GitHub:

1. Abra <https://github.com/settings/emails>.
2. Marque **Keep my email addresses private**.
3. Marque **Block command line pushes that expose my email**.

### Passo 2 — Criar o repositório

1. Abra <https://github.com/new>.
2. **Owner:** `drizaogythub97` · **Repository name:** `telegrana`.
3. **Description:** `Bot de Telegram com IA para as finanças da família`.
4. **Visibility:** **Public**.
5. **Não** marque *Add a README*, *.gitignore* nem *license*. O repositório precisa nascer vazio, porque o agente envia o conteúdo local.
6. Clique em **Create repository**.

### Passo 3 — Proteções de segurança (Advanced Security)

No repositório: **Settings** → na barra lateral, seção *Security*, **Advanced Security**. Ative (**Enable**) cada item:

| Item | Ação |
|---|---|
| **Private vulnerability reporting** | Enable |
| **Dependency graph** | deve estar ligado (vem ligado em repositório público) |
| **Dependabot alerts** | Enable |
| **Dependabot security updates** | Enable |
| **Secret Protection** | Enable |
| **Push protection** (aparece depois de ligar o Secret Protection) | Enable |

Deixe **Code scanning** como está: o agente configura o CodeQL na S1, quando houver código.

### Passo 4 — Actions (o CI)

Em **Settings** → **Actions** → **General**:

1. **Approval for running fork pull request workflows from contributors:** escolha **Require approval for all external contributors**. Qualquer pessoa pode abrir PR num repositório público, e isso impede que o código de um estranho rode no nosso CI sem você aprovar.
2. **Workflow permissions:** escolha **Read repository contents and packages permissions** e **desmarque** *Allow GitHub Actions to create and approve pull requests*.
3. Clique em **Save** em cada bloco alterado.

As regras de proteção da branch `main` o agente cria pela API na S1.

### Passo 5 — Acesso do Claude Code

O `gh` desta máquina já está autenticado como `drizaogythub97`, com os escopos `repo` e `workflow`. No PowerShell (na pasta do projeto):

```powershell
gh auth status
gh auth setup-git
```

O primeiro comando deve mostrar `Logged in to github.com account drizaogythub97`. O segundo faz o `git` usar o login do `gh`, sem pedir senha.

Se o `gh` não estiver autenticado: `gh auth login` → **GitHub.com** → **HTTPS** → **Login with a web browser** → copie o código mostrado e confirme no navegador.

## 6. Erros comuns

| Sintoma | Causa e solução |
|---|---|
| Não aparece *Secret Protection* em Advanced Security | O repositório ficou privado. **Settings** → **General** → *Danger Zone* → **Change visibility** → Public. |
| `gh: Not Found (HTTP 404)` no check | `GITHUB_REPO` com dono ou nome errado, ou o `gh` está logado em outra conta (`gh auth status`). |
| Push recusado com `GH007: Your push would publish a private email address` | Funcionou como esperado: algum commit saiu com o e-mail pessoal. Avise o agente, que corrige a configuração local. |
| `fork-pr-contributor-approval` aparece como AVISO | A API não respondeu para o seu plano. Confira o passo 4.1 na tela. |
| Criou o repositório com README | Não tem problema: avise o agente, que integra o histórico sem apagar nada. |
